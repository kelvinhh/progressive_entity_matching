## 实现约定及与原文的差异

| 项目 | 当前实现 |
| --- | --- |
| 文本 | 指定属性值拼接；Unicode NFKC、casefold、压缩空白；不使用列名、ID、标签 |
| TF-IDF | 跨表时联合两表拟合；单表时拟合一次。idf=log((1+N)/(1+df))+1，计数乘 IDF 后 L2 归一化；这是明确选择的平滑变体 |
| 候选 | 只返回有正相似度的 top-k，不用零分边补齐；相似度相同按字符串 ID 排序 |
| 单表候选 | 每条记录先取 k 个非自身邻居，再规范化无向边并求并集；最终节点度数可以大于 k |
| 跨表调度 | 默认只对左侧节点按邻域平均权重排序；可配置为右侧。不同表相同 ID 是不同节点 |
| 单表调度 | 两端都建邻域；重复邻接项占本地轮次位置，但只在第一次出现时输出和计入预算 |
| BFS | 每轮按节点顺序取邻域的下一个位置；不等同于普通图 BFS |
| Hybrid | 每个节点先取最优边，全局按边权排序；之后按节点平均权重依次输出剩余邻域 |
| EC | 为实现清晰采用全量排序，未采用仅保存预算内边的堆优化 |
| 核验 | 真实标签模拟完美核验器；不训练实际匹配模型 |
| PR@B | `progressive_recall` 采用 sum(R(b), b=1..B)/B，候选耗尽后保持召回；新增 `pyjedai_auc` 使用实际输出数 L+1 归一化且不补尾部，已对照固定版本的方法 |
| 时间 | 所有策略共享候选生成时间；调度在最大预算处计时一次并在多预算行中标注；核验耗时不计入算法时间 |
| 内存 | 合成示例启用 tracemalloc；真实基线关闭 tracing。第二阶段每个算法使用独立进程测量整体峰值 RSS，包含解释器与输入加载，不声称算法增量内存 |
| 当前数据 | 合成商品示例 + D1/D2 真实跨表数据 + Cora 单表镜像变体；Cora 规模与论文不同，已记录 |

召回率始终以**全部真实匹配数**为分母，未进入候选集的真匹配仍计为漏检。
若预算超过候选数量，指标中同时记录实际比较数，曲线文件仅列实际比较位置。

## 对导读的补充

导读将四种调度作了直观概括。实现时必须再区分两点：

- 跨表任务只调度一个分区即可，不需要把左右表节点混在同一排名中。
- Hybrid 的第一阶段是将各节点的最优边**全局按边权排序**，与按节点均值顺序输出的 BFS 第一轮可能不同。

参考：Maciejewski et al. (2025), DOI 10.1145/3709715，§§3、5.2、6、7.1。
